# inline-css 5.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This document authorizes planning only; implementation and publication are separate actions.

**Goal:** Resolve 16 reviewed issues: the original ten plus backlog additions B11, B12, B14, B16, B17, and B18, with explicit resource permissions, bounded loading, correct CSS and template handling, truthful runtime support, and a tested npm release.

**Architecture:** Keep the CommonJS Promise API and the existing workspace structure. Share resource policy between the file and HTTP loaders, retain stylesheet document order, and preserve declarations until serialization so the browser can resolve shorthand relationships correctly. Release breaking workspace changes alongside the root package.

**Tech Stack:** Node.js, npm workspaces, Cheerio, Axios, PostCSS plus a selector parser, Mocha, ESLint, Changesets.

**Spec:** The user's requested 5.0.0 release covering the original ten findings and the six required additions in [the additional backlog](../../backlog-after-top-ten.md). Scope updated 2026-11-09. The maintainer selected the highlighted compatibility choices: Node 22.12+, explicit resource permissions, finite configurable limits, direct-only loading, rejection of selector-removal conflicts, validation of known options with Error rejections, corrected serialization, retained root API and independently versioned workspace changes. See [compatibility decisions and measured evidence](../../validation/2026-11-09-compatibility-decisions.md). Numeric limits remain RC candidates pending production validation; exact new interfaces remain implementation proposals.

**Scope boundary:** B13, B15, B19–B24, and a new public diagnostics API remain outside the required release scope. Narrow internal-error handling associated with B25 is included in B18's fix; it is not a seventeenth issue. Broader nested-media support, asset URL rebasing, attribute-helper redesign, and benchmark-driven new limits require a separate scope decision.

## Proposed design and constraints

- Runtime: `engines.node: >=22.12.0` on every published package. Test the exact floor and current patches of Node 22, 24, and 26. Recheck dependency engine requirements before locking versions; do not silently raise this floor.
- Preserve `inlineCss(html, options) -> Promise<string>`, CommonJS imports, existing template protection, `data-embed`, XML handling, and existing apply/remove options. Keep `options.url` required in this release; reject missing values with an `Error` and stop before extraction.
- External stylesheet access is denied by default. Existing inline styles, embedded styles, and `extraCss` need no resource permission. If `applyLinkTags` is false, do not fetch or authorize those links. If fetching is requested but denied, reject rather than silently remove the stylesheet.
- Add `options.resourcePolicy`, normalized by a new shared workspace package, with these RC candidate defaults. Do not treat the numerical values as final until the validation gate in Task 4 passes:

  ```js
  {
      allowedOrigins: [],       // exact HTTP(S) origins; no wildcards
      fileRoot: null,            // absolute directory, or null to deny files
      allowPrivateNetworks: false,
      timeoutMs: 10000,          // whole conversion's resource-loading deadline
      maxStylesheetBytes: 1048576,
      maxTotalBytes: 10485760,
      maxStylesheets: 32,
      concurrency: 4,
      maxRedirects: 5
  }
  ```

- Validate policy values before I/O: finite positive integer limits, nonnegative integer redirects, strict booleans, valid origin strings without credentials, and an absolute existing directory for `fileRoot`. Partial policy objects inherit defaults without mutating caller data. No unlimited setting in this release.
- Permit HTTP(S) only for allowlisted origins. Reject URL credentials and other schemes, including `data:`. Check every redirect. Deny non-public IPv4/IPv6 destinations unless `allowPrivateNetworks` is explicitly true; that flag does not bypass the origin allowlist. Validate all resolved addresses and connect using the validated resolution to prevent DNS rebinding.
- File permissions use canonical root and target paths, including symlink resolution and path-segment containment. File URLs from an HTTP base still require `fileRoot`. Do not claim this protects against a hostile process concurrently changing the authorized filesystem.
- Resolve proxy support as direct-only for 5.0: explicitly set `proxy:false` on the loader's isolated Axios client, remove its direct `proxy-from-env` dependency, and do not mutate application environment variables or global Axios defaults. Test uppercase/lowercase HTTP_PROXY, HTTPS_PROXY, ALL_PROXY and NO_PROXY with a proxy sentinel. Configurable proxy transports and custom agents are out of scope. Document a proxy-aware application-prefetch migration that retains source order/media and makes clear those supplied bytes are outside built-in loader budgets.
- Validate known options while tolerating unknown keys for wrapper compatibility. Standardize failures on `Error` objects with stable codes: `ERR_INLINE_CSS_INVALID_OPTIONS`, `ERR_INLINE_CSS_RESOURCE_DENIED`, `ERR_INLINE_CSS_RESOURCE_TIMEOUT`, `ERR_INLINE_CSS_RESOURCE_LIMIT`, and `ERR_INLINE_CSS_SELECTOR_RETENTION_CONFLICT`. Preserve causes and propagate unrelated internal errors without relabeling them.
- Enforce byte limits while reading, including decompressed HTTP content, not only after buffering. Bound file reads too. Resource failure aborts outstanding requests and queued work; all callbacks settle exactly once.
- Correct CSS output may contain multiple declarations for the same property. Preserve fallback declarations and shorthand/longhand semantics; do not promise alphabetical style serialization or byte-identical 4.x output.
- Treat absent, empty, or `all` media attributes as unconditional. Other media conditions on style/link elements must never become unconditional inline declarations. Do not invent a viewport or evaluate conditions during conversion. With `preserveMediaQueries:true`, retain conditional CSS from embedded styles, authorized linked stylesheets, and `extraCss`; with preservation disabled, omit conditional rules when their source tags are removed, while honoring explicit tag-retention options.
- When `removeHtmlSelectors:true` would coexist with retained nonempty CSS or a retained stylesheet link, reject with an `Error` before selector removal. This includes preserved media, `data-embed`, and explicitly retained style/link tags. Do not attempt selector dependency analysis. Empty style blocks alone do not trigger this rejection.
- Template delimiters are literal nonempty strings. Merge custom block kinds with the EJS/HBS defaults without mutating caller options; reject malformed definitions with an `Error`. Use one shared helper across all three parsing stages, collision-free generated placeholders, and exact restoration of generated tokens only. Resolve overlaps by earliest start, then longest opening delimiter, then block-key order; end a block at the first matching closing delimiter, without nested parsing. Leave unmatched opening delimiters unchanged.
- Store CSS declarations in arrays or own-key-safe collections. Unknown names such as `constructor`, `toString`, and `__proto__` must not hide valid declarations, alter prototypes, or be mistaken for internal fields. Skip only recognized unsupported/invalid selector failures; propagate internal errors through the existing Promise/callback error channels.
- No new CSS feature expansion beyond what is needed for correct parsing, specificity, and the reviewed cases. Preserve unsupported at-rules according to existing options; do not start fetching `@import` resources.
- No implementation, dependency installation, version mutation, commits, or publication is part of creating this plan.

### Alternatives considered

1. Patch existing comparisons and add individual shorthand expansions. Smaller initial diff, but retains the lossy declaration model and creates an expanding list of shorthand exceptions.
2. **Recommended:** retain declaration records, sort by cascade precedence, and let CSS serialization preserve shorthand relationships. A larger internal change, but addresses findings 4, 5, 8, and 10 together without inventing a full CSS value engine.
3. Replace the entire inliner with another engine. Potentially less owned code, but requires a much wider compatibility audit of templates, serialization, and options than this release needs.

The earlier review ran on Node 22.12.0: 63 tests passed; lint had zero errors and three warnings. | Loaders | `packages/href-content/index.js`, `packages/remote-content/index.js` | Enforce policy at I/O boundary; bounded reads and requests |
| Extraction | `packages/list-stylesheets/index.js`, `packages/style-data/index.js`, `packages/extract-css/index.js` | Ordered sources, tag handling, bounded scheduling |

| CSS parser | `packages/css-rules/index.js` | Parse selector lists and ordered declarations |

| Release | Manifests, lockfile, `.github/workflows/main.yml`, `turbo.json`, `.changeset/`, README files, new `docs/migration-5.md` | Runtime support, reproducible checks, package versions and migration |

Proposed exact interfaces:

```js
// resource-policy (new workspace package)
normalizePolicy(input = {}) -> Policy
authorizeUrl(url, policy) -> URL                 // throws Error on denial
authorizeFile(url, policy) -> Promise<string>   // canonical authorized path
createLookup(policy) -> NodeLookupCallback      // authorize DNS answers used by socket

// inline-css-template-blocks (new workspace package)
protect(html, codeBlocks = {}) -> { html: string, restore: (html: string) => string }
// Defaults are merged internally; validation throws Error before parsing.

// Public callback APIs: new options parameter is a breaking change.
getRemoteContent(url, options, callback)         // options.resourcePolicy
getHrefContent(destHref, sourceHref, options, callback)
// callbacks: (error: Error | null, content?: string) => void

// css-rules v2
parseCSS(css) -> Array<{
    selector: string,
    declarations: Array<{ property: string, value: string, important: boolean, order: number }>
}>

// Internal declaration record; all specificity entries are numbers.
// An important flag NEVER replaces the original specificity.
// sourceOrder increments across ordered sources; declarationOrder is local.
// origin is 'stylesheet' or 'inline'.
{ property, value, important, specificity: [a,b,c,d], sourceOrder, declarationOrder, origin }
```

The extraction entry point `extractCss(html, options, callback)` stays the same. Its callback becomes `(err, html, css, metadata)`, where the additive fourth argument is `{hasRetainedCss: boolean}`; existing three-argument callbacks remain valid. Root `inlineContent` rejects the B14 option combination using that metadata before invoking selector removal. Include original retained styles and links in metadata, even when their apply flags are false.

Internally, enumerate `<style>` and stylesheet `<link>` nodes in one document-order traversal before removing tags. Apply shared template protection before that traversal. A source record is `{kind: 'embedded'|'linked'|'extra', order, media: string|null, css?, href?, sourceUrl?}`; `media` is null for unconditional sources. Retain source URL provenance without implementing asset rebasing. Fetch in bounded parallelism, then process by `order`; append `extraCss` after extracted CSS as today. Return only unconditional declarations for inlining.

With preservation enabled and source removal requested, replace each conditional source's removed tag with a style tag containing its conditional CSS at that source position; linked unconditional CSS is inlined while its media rules are retained there. Emit preserved `extraCss` media rules in a final style tag in the document head (or XML root in XML mode). Preserve wrappers and rule order; never duplicate CSS already retained by `removeStyleTags:false` or `removeLinkTags:false`. A conditional media attribute must wrap the source's preserved rules, including any inner media conditions. Full support for previously unsupported nested-media inputs remains deferred as B13; the B11 wrapper must still retain both outer and inner conditions without flattening them. Keep standalone list/style extraction APIs working; result additions must be backward compatible.

## Review focus

1. Redirects, IPv4-mapped IPv6, mixed DNS answers, and DNS rebinding must not evade authorization; Task 3.
2. Symlinks, encoded traversal, sibling-prefix paths, and platform file URLs must not escape `fileRoot`; Task 3.
3. Slow headers, slow streams, compressed bodies, and callback races must obey limits and settle once; Task 4.
4. Important inline styles, repeated selectors, fallbacks, and shorthand relationships must retain browser semantics; Task 6.
5. Published consumers must resolve released workspace dependencies without local symlinks or a repository lockfile; Task 9.

Additional required checks: template collisions and literal delimiters (Task 1a); inherited CSS keys and error propagation (Task 6); conditional sources and selector-removal conflicts (Task 7). All six backlog additions have explicit release gates below.
